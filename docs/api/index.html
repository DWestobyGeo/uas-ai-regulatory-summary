API Query-parameter access to state UAS regulatory data

← Browse the site

Current API (v1) available now

This is a static, read-only API served directly from files in this repository via GitHub Pages — there is no server, so there are no rate limits, no auth, and no uptime beyond GitHub Pages itself. There are two equivalent ways to get the same data:

1. Query-parameter endpoint (this page)

Fetch this page with a state parameter and it returns that state's full JSON record instead of these docs:

GET /api/index.html?state=TX

Try it: ?state=TX · ?state=CA

2. Direct static JSON file (recommended for scripts/integrations)

The query-parameter endpoint above is just a thin JavaScript wrapper around this same file — fetching it directly is faster and doesn't require running JavaScript:

GET /data/v1/{STATE_ABBR}.json

Example: /data/v1/TX.json

Parameters

ParamTypeRequiredDescription
statestringYesTwo-letter USPS state abbreviation, case-insensitive (e.g. TX, ca). Must match an entry in /data/v1/index.json.

Discovery endpoint

To see which states are currently available (this project covers all 50 states over time, not just the ones live today), fetch the index:

GET /data/v1/index.json

Response shape — state endpoint

Both access methods return the same JSON object:

FieldTypeDescription
schema_versionstringVersion of this JSON shape. Breaking changes bump this and the URL prefix (see Versioning below).
statestringFull state name.
state_abbrstringUSPS two-letter abbreviation.
state_fipsstringTwo-digit FIPS state code — useful for joining to other geographic/boundary datasets.

summary_markdownstringThe full human-readable regulatory summary, as Markdown text. The website renders this client-side; API consumers can render it with any Markdown library or use it as plain text.

source_filesobjectRelative paths (from the site root) to the original Markdown summary and CSV source register files, for download.

Example

fetch("https://<your-username>.github.io/uas-ai-regulatory-summary/data/v1/TX.json")
  .then(r => r.json())
  .then(data => console.log(data.record_count, "sources for", data.state));

Versioning

The current API is v1 (see the /data/v1/ and /api/v1/ paths — this page is aliased at both /api/ and /api/v1/). Once published, v1's URL shape and field names will not change in a breaking way; new fields may be added. A breaking change will ship as /data/v2/ / /api/v2/ alongside the old version, not as a silent replacement.

Roadmap planned, not yet available

This is a static file-based API today. Planned future capabilities, most of which will require a real backend rather than static files, include:

  • Point query — e.g. ?lat=30.27&lon=-97.74 — return the state (and eventually county/local) authorities applicable at a coordinate.
  • Extent / bounding-box query — e.g. ?bbox=west,south,east,north — return all jurisdictions intersecting an area, for project sites that span a state line.
  • GeoJSON / feature-service export — join the state_fips field (already included in every record for this purpose) to authoritative state and local boundary data.
  • Local (municipal/county) and tribal records — currently out of scope; see each state's summary for the current scope note.

The state_fips field is included in every record specifically so today's data can be joined to boundary datasets later without a schema change.
